# Share-Card Audit (TASK 1)

Generated by Claude Code, autonomous session. Goal: every game, on completion, should produce a **shareable result card** = (a) copyable text with score/rarity + the `douknowball.com` URL, and (b) a downloadable **image** people can post.

## Method
- `src/components/game/ShareButtons.tsx` is the shared share UI. Grepped every page/board that renders it.
- `html2canvas` (image rasterizer) is a dependency but is used **only** in `src/pages/Profile.tsx` — no game produces an image card.

## Findings (before this change)

| Capability | Status |
|---|---|
| Copyable **text** card (emoji header + optional emoji grid + score + `douknowball.com/<path>`) | ✅ ~40 games via `ShareButtons` |
| Social share buttons (X, WhatsApp, Instagram, Gmail, Messages) | ✅ same ~40 games |
| Downloadable **image** card | ❌ **0 games** — universal gap |
| Any share UI at all | ❌ missing on **Conquest**, **Fantasy Draft** |

### Games WITH NO share UI
- **NFL Conquest** (`src/pages/Conquest.tsx`) — no `ShareButtons`.
- **Fantasy Draft** (`src/pages/FantasyDraft.tsx`) — no `ShareButtons`.

## Resolution applied
1. **Image card built into `ShareButtons`** (`ShareCard.tsx` + a "Save image" action). Because the image generator lives inside the shared component, **all ~40 games that already render `ShareButtons` gain the image card automatically** — no per-game wiring needed. This is the "most-played first" rollout by construction: Football Grid, the career games, and the grid games all use `ShareButtons` and light up immediately.
2. The capture node is styled with **inline hex colors and system fonts**, not Tailwind classes, because `html2canvas` cannot parse `oklch()` colors (which the Tailwind theme uses) and would otherwise throw.
3. **Conquest** and **Fantasy Draft**: `ShareButtons` added at their completion state (see their commits).
