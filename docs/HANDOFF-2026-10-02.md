## 2. The database incident, and the rule it left behind

From about 00:10 to 02:49 EDT on 2026-10-02 the production database (Supabase `flawuiqbvjobmkfkauhw`) did not answer.
The cause, as far as it can be known: the project was running on **Nano** compute (0.5 GB of memory, 5 MB/s disk
baseline) although the organization pays for Pro, and it had taken a day of very heavy reads from both lanes, four
data migrations at midnight, the Eastern midnight rollover, and then this lane's release gate against the live tables
(about 40 harnesses plus a 546 page browser sweep, more than once in an hour). The owner restarted it, raised the disk
from 2 GB to 8 GB (free), and the free Nano to Micro change went in at 02:49. Players lost every game that reads the
database for two and a half hours. Full account: the INCIDENT section of `docs/PROJECT-STATE.md`.

**The standing rule. It binds you and every agent you start:**

1. **Production load is a budget.** One live reading pass and one browser sweep per release. Never two lanes of live
   readers at once. Nothing heavy in the half hour after a data migration or around midnight Eastern.
2. **Agents never touch production.** No live harness, no bake without `--dump`, no browser walk that can reach the
   host, no MCP SQL. The rule is the last line of `briefs/RULES.md` in the kit (section 7); put it in every brief.
   When a round needs table data, the lead pulls it ONCE into a file and the builder works from the file
   (`pullMarketDump.mjs` in the kit did that for Round 876: twelve requests, 0.2 s each).
3. **A gate script must skip harnesses that reach the live project.** `gate-s.sh` in the kit does it with a grep for
   the client import and lists them as SKIPPED-LIVE. Codex's Round 872 is building the same guard into
   `scripts/runAllSims.mjs`; until it lands, never run `runAllSims` blind.
4. **If REST slows** (57014 on trivial reads, PGRST003, header timeouts): stop everything first, look second.
5. **Recovery is the owner's.** The MCP has no restart. Never pause or restore production. A compute size above
   Micro is money and his decision.

## 6. Traps this session paid for

- **The gate clone is `C:\Users\antho\dukb-gate`** (CRLF, real origin). Never gate in the shared checkout: Codex has
  uncommitted work there. Never `git add -A` anywhere.
- **Never build while a harness or a browser pass is reading `dist`**, and never run two bundling harnesses with the
  same TEMP: give each lane its own `TEMP` and `TMP` (Windows style paths, `C:/Users/...`).
- **Git Bash rewrites `/route` arguments**: prefix `MSYS_NO_PATHCONV=1`. A `cd X && (...) > log & export ...` chain
  runs the rest in the wrong directory. A foreground `sleep N; cmd` is blocked: use `until ...; do sleep 5; done`.
- **Bash heredocs lose backslashes and break on apostrophes**: write scripts with the Write tool; commit messages
  through `git commit -F - <<'MSG'`.
- **What's New conflicts**: keep both sides (`resolve_both.py`), then check for a duplicated entry
  (`dedupe_whatsnew.py`); `searchKeywords.json`: take theirs and rerun `node scripts/genSearchKeywords.mjs`;
  `lastmod.json` and `sitemap.xml`: take main's and rebuild.
- **A harness green means its closing summary line and its real exit code**, never a filtered grep. `timeout`
  reports 124 on a slow harness and it reads as a red that was never there: several Club Manager harnesses need 25
  to 50 minutes on a loaded machine.
- **supabase-js resolves `{data: null, error}` on an HTTP error.** Code and harnesses must check `res.error`.
- **Workflow agents are restarted after 180 seconds without progress, and one long command is exactly that.** The
  type gate takes three to five minutes here and most Club Manager harnesses far longer, so the old "four minute"
  rule killed Round 876's builder twelve times (the workflow's own error: "agent stalled on all 6 attempts"). Agents
  now keep every command under 150 seconds and start anything longer through `detach.sh` and poll it with
  `waitfor.sh` (both in the kit; `briefs/RULES.md` has the rule). Still: no `run_in_background`, no Monitor, notes
  file, push after every commit. The lead starts its own long gates the same way (a hidden bash through PowerShell
  `Start-Process`), so nothing it runs sends a completion notice into a running workflow.
- **An invoice line is not the instance.** The bill said Micro while the project ran Nano. Read the dashboard.
- **The clock in early board entries of 2026-10-01 was guessed and ran about 40 minutes fast.** Trust `date`.
