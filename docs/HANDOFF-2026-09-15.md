## 3. Round 585, what the adversarial review changed (already fixed in the tree)

All of this is written up in the design doc's 585 As built section; the short version:

- **Every player drew the same packs.** The ledger seed was a constant, so the free Scout Pack was
  the same kid for everyone and the sequence could be read off the public repo. A ledger now takes
  `freshSeed()` the first time it is stored (S12, control `sameseed`).
- **"Welcome him in" could delete a kid who never reached a bed**, and a lost ledger swallowed packs
  until its numbers caught up with the academy. A pack can only be dismissed once delivered, and the
  next pack's number runs past `packsDelivered` (`nextSeq`, `minSeq`; S13, vitest 6 and 7).
- Opening a pack no longer records a session mark (safeguard 2: packs never touch streaks); a stored
  kid is sanitised into his tier's band on delivery; a name clash no longer moves the scouts'
  seed; "a draw" became "a watched draw" in the panel, the stadium rules modal, the guide and the
  ledger's own header comment (away draws pay nothing); the academy guide says a pack kid's band is
  known.
- **Stated, not fixed:** a stale background tab that saves last can roll the stadium match count back,
  after which gems pay nothing until live play passes the credited count again; the ledger writes
  before the stadium save, so a crash in that window loses gems but never gains them; and two visible
  tabs can each play a match on the same save.

## 6. Traps hit this session, and the fix for each

- **Bash heredocs eat backslashes and `$`** in node code on this machine (`\\n` becomes a newline,
  `$` before a brace vanishes, `\'` loses its backslash). Write any script with regexes, template
  literals or escaped quotes through the Write tool into the scratchpad and run it from there, or use
  Edit directly. Every patch script this session that went through a heredoc had to be redone.
- **A long gate hits the 600 second tool limit.** Run the suite, `build:seo` and the controlled
  harnesses with `run_in_background`, and wait with an until-loop on the output file. Do not stack
  many waiting loops; each leaves a task behind.
- **Never run harnesses while `build:seo` runs, and never edit while the suite runs.** The suite
  bundles each harness as it starts.
- **The M2 number scan in `simTycoonHelp` reads every word on the stadium screen.** A pronoun ("the
  faded one") or a new number word in the page, the hook or `TycoonPitch.tsx` turns M2 red, and a number
  in an engine blurb turns L1 red. Reword, or add a claim or an
  idiom with a reason; never loosen the scanner.
- **A control that edits text must still match after you change that text.** Several harnesses
  (`simTycoonHelp`, `simTycoonPitch`, `simTycoonLoads`, `simTycoonRooms`, `simTycoonAway`,
  `simTycoonAwayMatchdays`, `simTycoonLeague`, `simTycoonPacks`) rewrite exact lines of the page, hook
  and libs; changing one of those lines aborts the harness with "does not carry exactly one"
  (`simTycoonAway` says "the Round 439 visibility settle is not in useStadiumTycoon.ts" instead).
  Update the anchor with the code.
- **This handoff was fact-checked against the repo** by six read-only agents before it was committed;
  their corrections (the sitemap must ship, eighteen controls not nineteen, the orphan check, the
  board's run-on line, the unmeasured pace gate) are folded in above.
- **Adversarial review earned its keep every round**: 584 and 585 both had real defects past every
  green gate. Run it (a background general-purpose agent, read-only, probes in a temp folder outside
  the repo) before committing any round that changes a rule, a save or a reward.
- **Lovable sync lag**: `deploy_project` right after a push builds the previous commit. Wait for
  `latest_commit_sha`.
- Files can show as modified from line endings alone after a build; check with `--ignore-cr-at-eol`
  before staging. But when `scripts/data/lastmod.json` changes, `public/sitemap.xml` changes with it and
