## 5. How a release runs (session H's recipe, proven on BB and BC)

1. Briefs: for a numbered round, read only DIGESTERS write `proposed-head-<n>.md` from a draft plus critic (or a brief
   writer writes `brief-<n>.md` from PLAN.md, the critic and the hunts); the lead edits and assembles
   (`briefs\assemble.mjs`), then `roundsG.js` with the rounds.
2. Join: the lead writes `brief-<X>G.md` (model: `brief-BCG.md`) with a rulings file for every open item, then one
   integrator via `roundsG.js` (`reviewers: []`).
3. Gate prep: ONE agent from the join report (model: the gate prep workflows of BB and BC): budgets committed with their
   causes, `gate-<x>-*.txt`, the ENV entries in `mkGateReqG.mjs`, `rc-R`, `rc-K`, `rc-V`, `rcl`, `sendGate.sh` in the
   gate worktree's `.tmp-fx`. It sends nothing; the lead reads its doubts and the sender, then runs `sendGate.sh` in
   the background (its gateWait wakes the chat).
4. Publish: read every non green line (rerun a timing red ALONE once); apply the build output
   (`rcg\applyBuildOutput.mjs`); `rc-pub`; push the gate branch to main (a fast forward that keeps every merge commit);
   wait for `get_project`'s `latest_commit_sha`; `deploy_project`; prove (deployment id, What's New lines, routes, a
   browser console read); fill the record (`fillRecord.mjs`) and prepend it (`prependDoc.mjs`) to the board and the
   state doc from `lead-docs`.
