## Change and compatibility

Application changes are confined to `src/lib/soccerCareerSave.ts` and the existing restore/write calls in `src/pages/SoccerCareer.tsx`. The serializer keeps saves of at most 60,000 JavaScript characters as literal JSON. Larger saves first use the already installed `lz-string` UTF16 codec for the complete `seasons` and optional `story` arrays, keeping that existing representation byte-identical whenever it fits. If it still exceeds 60,000, a distinct `lz-string-utf16-career` envelope can hold the complete original JSON. The serializer chooses the smallest candidate. Original currentClub/age/retired metadata stays available to home Continue; every logical field and history remains in the payload. No dependency, engine, real data, Manager, gameplay or interface feature changed.

The parser supports literal legacy arrays, the existing `lz-string-utf16` histories and the complete-career envelope. It unwraps the latter and still checks claimed inner histories before handing the restored object to the existing validator and migration. Unknown logical fields survive. A claimed malformed or future history envelope refuses before optional story repair, so unreadable packed histories are refused instead of being discarded by that repair. Existing non-envelope legacy story repair stays intact. The save failure warning and retry continue to use the current career without replaying a season.

The original `simCreation` limit remains 60,000. It now measures the actual serializer and checks complete JSON restoration. Its separate 900-character added-field limit still uses the raw field delta. SaveKeeper's Soccer-only fixture writer/readers and two existing long-career test readers use the same codec; their gameplay assertions and the other games' writers are unchanged. Two save-retry copied-fault anchors follow the actual serializer call; their outcome assertions and effective-control requirements remain unchanged.
